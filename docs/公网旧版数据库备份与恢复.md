# 公网旧版数据库备份与恢复

本方案针对上一轮只读核对记录中的旧结构`c2e41a9f3b67`，不是根据“缺几张表”猜测版本。当前已交付兼容代码与本地隔离演练；**本轮没有连接服务器、真实OSS、读取真实凭据、迁移公网库或发布**。实际执行前仍需重新核对现网revision、镜像/卷身份及维护窗口。[本轮验证证据](task-evidence/2026-10-26-legacy-site-backup.md)

## 支持范围

沿用`scripts/site_backup.py`的备份、校验、恢复流程和bundle v1格式。默认依旧要求当前Alembic head，只有备份时显式选择`--schema-revision c2e41a9f3b67`才接受旧库；未知版本、中间迁移版本和伪造stamp均不接受。校验与恢复从清单中的实际revision选择严格规则，不接受清单中的`head`别名。

旧结构配置档为`ops/site-backup-profiles/c2e41a9f3b67.json`：22表（含迁移表）、161列，以及类型/空值/默认值、PK/FK/唯一/检查约束和索引语义。它从仓库前四次真实迁移生成的干净PostgreSQL16子库冻结，包含迁移源码LF归一化SHA-256；不会运行时从待备份数据库生成期望值。

PostgreSQL16的导出/恢复会重写8个CHECK表达式。配置档只接受干净迁移与其真实dump/restore产生的两种完整字符串表示，再与基础目录精确比较；不通用替换SQL、不忽略约束，也不接受任意第三种表达。延迟约束、未验证FK、主键INCLUDE等变化仍拒绝。

## 备份内容与一致性

- 全部旧public表和所有账号，包括角色、状态、密码哈希、组织、私人笔记、历史版本、回收站、页面、审计、通知及任务。
- 所有`files.object_key`和`file_variants.object_key`对应字节，按原件/变体合并引用；旧版本不查询尚不存在的PDF/AI运行表。历史和回收站引用不会因当前页面删除而遗漏。
- 同一个只读可重复读导出快照用于表指纹、引用清单和真实`pg_dump -Fc`。对象系统不受数据库快照冻结，必须先停止所有写入者并确保对象期间不覆盖/清理。
- OSS读取保留所选version ID；无版本号时按ETag条件读取。归档保存实际对象字节和新计算的SHA-256，并记录版本/ETag；不是只保存对象名称或远端URL。
- 就绪/处理中原件、已接收上传与所有变体必须存在。按既有状态允许缺失的未上传/过期/拒绝原件会明确登记；403、网络失败、读取中变化不算“可选缺失”。

继承现有每对象50MiB、归档20GiB、dump2GiB、清单32MiB、100万个数据库行和10万个对象的上限。不包含整个桶的所有历史版本/孤儿对象、数据库全局角色、RAM权限或Bucket策略。只接受可信操作者创建的备份，dump会在目标执行SQL，不能作为接收不可信上传的接口。

## 操作前提

以下只是后续获授权时的操作说明，本轮没有执行服务器命令。

1. 使用包含当前兼容工具、profile目录和项目后端依赖的**独立可信工具目录**，无需覆盖仍在运行旧镜像的服务器工作副本；不要先升级源数据库来适配工具。
2. 连接使用显式本机回环地址、端口、用户名、库名；工具会与指定容器核对PostgreSQL16及同一集群身份。若需要增加宿主机回环数据库映射，按独立维护变更核对原容器/卷，不能自动应用或开放公网数据库端口。
3. 私密单行URL文件只给本机路径，不把连接值放命令参数。源与目标URL分开，目标必须是新建`notes_restore_site...`命名的空数据库和独立空对象目录。
4. 维护窗口确认所有API、Worker、迁移、定时任务和其他数据库/对象写入者已停止，并记录原运行状态。确认参数本身不会停止服务；失败时按记录恢复原服务，不继续迁移。
5. 归档含私人数据、密码/令牌哈希及旧加密凭据，目录0700、文件0600；Windows须配置受限ACL（访问控制列表）。不要提交、公开分享或输出清单中的私人对象键。环境/密钥/证书和实际部署文件另在受限位置备份，工具不会自动复制这些秘密。

## 旧库备份与校验

命令在完整工具仓库根目录，使用项目`backend/.venv`。示例路径和容器名须由操作者选择；文件中不放示例密码冒充实际配置，也不在聊天中粘贴真实值。

本地对象源：

```powershell
& backend/.venv/Scripts/python.exe scripts/site_backup.py backup --database-url-file '.local/legacy-source-url.txt' --postgres-container '已核实的源数据库容器名' --storage-backend local --storage-root '已核实的源对象目录' --output '.backups/legacy-本次唯一批次' --schema-revision c2e41a9f3b67 --maintenance-confirmed
& backend/.venv/Scripts/python.exe scripts/site_backup.py verify '.backups/legacy-本次唯一批次'
```

未来获准使用真实OSS时，仅把存储参数换成`--storage-backend oss --env-file '私密OSS配置文件路径'`，不同时传`--storage-root`。配置文件沿用现有OSS变量；连接串仍只从单独URL文件读取。真实权限/版本读取、费用和对象恢复范围需在执行前说明并确认。

输出目录不得已存在；工具在相邻私密暂存目录完成全部校验后发布，失败不留下“成功备份”。返回退出0及`ok=true`才表示操作成功。清单的`schema_revision`必须为实际c2，表集合22张；查看清单时只投影这些非敏感字段，不直接打印全部对象条目。`verify`证明归档文件和清单自洽，不能替代真实空目标恢复。

## 空目标隔离恢复

不预先迁移目标库，也不恢复到已有开发库、业务库或上次失败的恢复目录：

```powershell
& backend/.venv/Scripts/python.exe scripts/site_backup.py restore '.backups/legacy-本次唯一批次' --database-url-file '.local/legacy-restore-url.txt' --postgres-container '已核实的隔离目标容器名' --storage-root '新建的空对象目录' --isolated-confirmed
```

恢复顺序为：归档再验证与只读快照副本 → PG16/集群核对 → 目标独占锁/空库和空目录核对 → 对象复制与逐字节哈希 → 原生pg_restore → 旧结构、全部原始行指纹和对象引用再核对 → 恢复目标运行态归一化。

归一化保留用户、角色和密码哈希，但撤销所有旧会话，删除文件读取票据、密码重置凭证及旧加密AI凭据，把排队/运行中的Job标为`site_restore_interrupted`。旧库没有AI运行/步骤表，不执行那些SQL。操作者需重新登录，未完成任务先人工核对，不自动重试外部付费调用。

成功报告包含`original_fingerprints_verified=true`、对象/行数和归一化计数。失败可能发生在两种阶段：

| 阶段 | 处理 |
|---|---|
| dump/对象损坏、版本或清单不合法，写入前拒绝 | 目标仍为空；保留原归档调查，不跳过校验 |
| 导入后发现指纹/引用不一致等 | 目标保留`.site-restore-incomplete`及现场，不能启动服务或覆盖重试；另选新空目标，不能删除原业务数据来“修复” |

恢复只写指定空本地对象目录，不上传或覆盖原OSS桶。这既可用于离线查看，也可作为后续迁移演练来源。重新接入OSS/恢复到新桶必须再制定独立目标、权限和对象上传校验步骤；不能把本地恢复通过写成“真实OSS已恢复”。

## 恢复副本升级演练与回退依据

只有旧库恢复报告通过后，才在**该隔离副本**执行：

```text
c2e41a9f3b67
→ d89f74a2136c
→ 16bd16083e39
→ 63b9d8343e02
→ 2ef16e7ca892
```

迁移工具必须在新进程中加载该副本的显式DATABASE_URL。当前`alembic/env.py`导入共享engine，仅修改Config中的URL不会切换库；不能在已连接源库的进程中临时改配置后自称“隔离”。私密URL不放命令行，不输出环境值。

本地自动测试使用全新子进程、禁用默认`.env`读取，逐段迁移后执行`alembic check`。按旧业务列投影比较迁移前后数据，而不是误把新增列造成的整行哈希变化当成数据损坏；新5张PDF/AI表初始为空，旧页面`pdf_page_number`为空，账号密码/所有者/历史与对象字节不变，源库仍保持c2。

公网更新前仍须使用**当次维护窗口的新备份**完成真实恢复演练，记录快照时点、耗时和配置/镜像/卷身份；过去日期备份只能作历史证据。旧镜像回退不会撤销数据库迁移；恢复旧快照会影响迁移后新增写入，需要先保存当前状态并取得明确确认，不自动downgrade或覆盖原数据库/OSS。

后续发布与回退统一见[IP HTTPS更新计划](superpowers/plans/2026-10-26-ip-https-public-update.md)。定时备份仍默认head，没有随本次开发启用或自动选择legacy；真实公网维护、备份timer、GC和通知均未执行。
