# 整站备份与隔离恢复

`scripts/site_backup.py` 是管理员在维护窗口运行的离线工具，备份整个应用数据库，以及数据库引用的原图、PDF、派生图和 AI 历史来源图片。它与 [账号 ZIP 恢复](账号归档恢复演练.md) 分开：整站备份保留所有账号、角色、密码哈希、组织、历史、通知和任务。

默认仍严格匹配当前Alembic head。已新增已知旧版`c2e41a9f3b67`的显式配置档，只有备份时指定`--schema-revision c2e41a9f3b67`才使用；旧结构、引用范围、恢复归一化和迁移演练见[公网旧版数据库备份与恢复](公网旧版数据库备份与恢复.md)。这是本地隔离验证通过的兼容路径，未执行真实公网或OSS恢复，不能通过忽略缺表或先迁移源库绕过校验。

本轮真实云端验收按用户决定暂缓，先交付工具、替身 OSS 测试与本机多账号演练。没有连接 ECS 或真实 OSS，没有发布新版本或复制本机共享模型 Key。定时备份、保留策略和失败通知另行实现。

## 一致性与范围

备份前由操作者停止 API、Worker、迁移和其他数据库 / 对象写入者，并确认期间不会有外部对象覆盖或清理。工具不自动停止服务器。`--maintenance-confirmed` 表示操作者已经完成这些准备；参数本身不会暂停服务。

数据库清单与 `pg_dump -Fc` 使用同一个 `REPEATABLE READ READ ONLY` 导出快照，记录所有应用表的行数与规范化内容指纹。PostgreSQL 快照不能冻结外部文件，因此维护窗口仍然必要。参见 [PostgreSQL pg_dump 同步快照](https://www.postgresql.org/docs/16/app-pgdump.html)。

对象集合合并 `files.object_key`、`file_variants.object_key` 和 `ai_runs.source.pages[].object_key`，包含回收站、失败处理原件及冻结的旧阅读图。已就绪 / 处理中原件、已接收上传、所有变体和 AI 引用必须存在；尚未上传、过期、已拒绝并按既有流程删除的原件可以缺失，清单明确记录。权限、网络错误不会当成对象缺失。存在对象逐一校验长度、可用的原件 SHA-256 和新计算的备份 SHA-256。

OSS 先读取 HEAD，再指定所选 `version_id` 下载；没有版本号时以 ETag 条件读取，拒绝读取期间内容变化。清单记录版本号 / ETag，恢复时从本地副本还原字节，不依赖 OSS 历史版本仍存在。官方说明见 [OSS 指定版本下载](https://www.alibabacloud.com/help/en/oss/developer-reference/download-a-versioning-object-using-oss-sdk-for-python-v2)。

这是数据库所引用对象的灾备副本，不枚举整个桶的历史版本、删除标记、孤立对象、RAM 授权、Bucket ACL 或生命周期策略。变体没有历史 SHA-256，无法证明备份前同长度替换未曾发生。

## 运行准备

在完整仓库中使用后端依赖环境和 Docker CLI。首版针对 PostgreSQL 16，操作者显式指定数据库容器；工具核对 Python 连接和容器内 PostgreSQL 的集群标识、库名与主版本，防止导出或恢复错库。连接串仅接受显式本机地址、用户名、端口和库名，不允许覆盖连接参数。

把连接串写在私密单行文件中，以 `--database-url-file` 传入路径，避免明文密码出现在命令行。Windows 不要用 PowerShell 文本重定向保存二进制 dump，工具已经通过 Python 二进制流处理。

以下示例的连接文件和目录都应由操作者选择，不能直接指向日常开发库、现有恢复库或其他人的备份。整站备份含密码哈希、私密笔记、令牌哈希及可能存在的旧加密凭据，须保存在受限目录，不能提交 Git、上传公开网盘或作为普通成员下载文件。工具不复制 `.env`、OSS 凭据或后端共享 Key；Windows 的目录 ACL 应由操作者配置，POSIX 权限位不能代替 Windows ACL。

## 备份、校验与恢复

本地存储备份示例（API / Worker 已停止）：

```powershell
backend/.venv/Scripts/python.exe scripts/site_backup.py backup --database-url-file '.local/site-source-url.txt' --postgres-container '专用数据库容器名' --storage-backend local --storage-root '专用源文件目录' --output '.backups/site-日期' --maintenance-confirmed
backend/.venv/Scripts/python.exe scripts/site_backup.py verify '.backups/site-日期'
```

OSS 使用 `--storage-backend oss --env-file '私密OSS配置文件'`，文件中沿用 `OSS_REGION`、`OSS_BUCKET`、`OSS_PREFIX`、`OSS_ENDPOINT` 与凭据变量。连接目标仍只取单独的连接文件，不从该配置文件挑选数据库。先经授权完成真实权限和版本读取验收，再用于云端；当前没有执行此步骤。

输出目录先在相邻私密临时目录完成，校验后发布，不覆盖已有备份。单对象、总大小、dump、清单与数据库行数均有上限；失败不会生成看似成功的成品。目录中的清单和 SHA-256 用于发现损坏，不提供来源签名。

格式 v1 包含 `manifest.json`、PostgreSQL custom 格式的 `database.dump` 和 `objects/`。对象副本以原键的 SHA-256 命名，原键、引用、选定版本及缺失状态只保存在私密清单中。上限为单对象 50 MiB、dump 2 GiB、清单 32 MiB、总量 20 GiB、100 万行和 10 万对象。`verify` 检查结构、长度与哈希；实际可恢复性需要另外执行空环境恢复。恢复会再建立私密副本，需要预留额外磁盘空间。

恢复示例：

```powershell
backend/.venv/Scripts/python.exe scripts/site_backup.py restore '.backups/site-日期' --database-url-file '.local/site-target-url.txt' --postgres-container '专用恢复数据库容器名' --storage-root '.local/site-restore/files' --isolated-confirmed
```

恢复目标必须是新建、尚未迁移的空库，库名以 `notes_restore_site` 开始；同时指定空文件目录。原有账号 ZIP 恢复工具要求预先迁移，这里的完整 PostgreSQL dump 自带结构，两种工具不能混用准备步骤。非空目标、别名 / junction、越界路径、损坏或超限备份被拒绝，不支持覆盖、合并或清库。

只恢复来源可信的管理员备份。完整 PostgreSQL dump 含可执行 SQL，校验哈希不能把不可信 dump 变安全；不要把陌生成员上传的文件交给本工具。恢复前消费经过校验的私密副本，恢复后对照全部原始表指纹与所有文件，再执行下述隔离处理。

## 恢复后的隔离处理

保留所有用户 ID、角色、密码哈希和业务内容，因此成员仍用原密码登录。为防止旧会话、下载票据或未完成任务在恢复环境自动生效：

- 撤销会话，删除文件票据、密码重置令牌和旧个人模型加密凭据。
- 排队 / 运行任务标失败并清租约和 Worker token；排队 / 运行 AI 转为中断，运行中步骤标失败，保留已有回答。
- 不启动 API / Worker，不恢复环境变量或共享模型 Key；独立预览必须显式设 `DEEPSEEK_API_KEY=''`。

上述调整在原始指纹核对之后执行，输出中单独报告数量。文件、上传记录和 PDF 业务状态原样保留；人工启动 Worker 前需检查过期且未完成的上传，既有 maintenance 仍可能按应用规则删除其原件。

数据库与文件系统没有共同事务。恢复中途失败或提交结果不确定时保留独立目标供核查，不能直接覆盖重试。应检查目标库、文件与输出错误码，重新演练时另建空库和空目录；不要为绕过保护而清理业务库。

Docker 客户端超时退出不保证容器内进程立即停止，因此超时也按恢复结果不确定处理：保持环境隔离，核对容器进程与数据库后再决定下一步。
