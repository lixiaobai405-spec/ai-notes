# 本地开发启动与停止

本机采用 Docker 中的持久化 PostgreSQL、`backend/.venv` 中的 API/Worker，以及 Vite 前端。云端已改为 Ubuntu，旧版部署及恢复有维护者交接记录；本轮新增功能的云端更新尚未执行，统一状态见 [M1 计划](M1开发与云端验收计划.md)。

## 首次创建管理员

在本机 PowerShell 中运行：

```powershell
cd D:\codex-pj\ai-notes\backend
uv run python -m app.cli create-admin --username admin
```

按提示输入密码两次，至少 10 位；输入不回显。成功后访问 `http://localhost:5173`，使用 `admin` 与自己设置的密码登录。初始数据库没有内置管理员或默认登录密码。

## 再次启动

先启动 Docker Desktop。在项目根目录启动数据库：

```powershell
cd D:\codex-pj\ai-notes
docker compose --env-file .local/postgres.env -f compose.dev.yaml up -d --wait
```

在三个终端中分别运行：

```powershell
# 终端 1：API
cd D:\codex-pj\ai-notes\backend
uv run uvicorn app.main:app --host 127.0.0.1 --port 8000 --no-access-log
```

```powershell
# 终端 2：Worker（后台任务进程）
cd D:\codex-pj\ai-notes\backend
uv run python -m app.worker
```

```powershell
# 终端 3：网页
cd D:\codex-pj\ai-notes\frontend
npm run dev -- --host 127.0.0.1 --strictPort
```

数据库迁移后再启动后端；更新了迁移文件时，在 `backend` 执行 `uv run alembic upgrade head`。迁移前的备份与云端更新流程仍按 M1 运维任务完善。

检查 API：

```powershell
Invoke-RestMethod http://127.0.0.1:8000/api/v1/health/ready
```

预期返回 `status=ok`。网页上传还需要 Worker 正常运行；真实 OSS 接口会产生相应云资源费用，自动验收使用生成测试图并限定范围。

## 停止与恢复

先在 API、Worker、网页对应终端按 `Ctrl+C` 停止进程，然后在根目录运行：

```powershell
docker compose --env-file .local/postgres.env -f compose.dev.yaml stop
```

恢复时再次按启动步骤执行，使用同一个私密数据库配置和数据卷。正常停止保留笔记数据；`down -v` 会删除命名数据卷，不属于停止步骤。修改 OSS 配置后，需要重新启动 API 与 Worker。
