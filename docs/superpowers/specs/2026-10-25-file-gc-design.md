# 文件引用保留与安全清理设计

状态：用户已确认“按完整安全清理工具开发（推荐）”。承接 M1 计划 T08 / T14 的统一引用感知 GC 待办。已有定时备份、PDF 框选与富文本选段未提交内容全部保留。本轮只交付代码、隔离测试和操作文档，不连接真实 OSS / 服务器，不对用户存储执行清理，不启用定时任务或提交代码。

## 方案选择

推荐方案 A：独立运维工具提供只读预演、维护窗口内清理、私密隔离归档和恢复。可以实际验证完整失败与回退流程，默认不删除。

方案 B：仅提供引用审计与预演，暂不交付执行器；实现更少，但不能关闭现有崩溃遗留对象的清理待办。

暂不采用在线自动 GC：数据库与对象存储不能共享事务，API 上传或失效 Worker 的在途 PUT 可能在检查后发布；当前没有统一对象生命周期日志，在线自动删除会扩大风险。后续如需在线 GC，应另行设计数据库状态机和写入协作。

## 引用与保留

1. 所有已登记 `File.object_key`、`FileVariant.object_key` 都保留，不因没有当前 NotePage 或状态 expired / rejected 就删除。它们仍属于账号归档与整站备份内容。
2. 当前页面、回收站、历史 `NoteVersion.snapshot.pages`、PDF 原件/导入/未完成任务、AI 运行冻结 object_key 与保存来源均参与保留图。文字来源钉住历史版本但不增加对象。历史版本、回收站和有效副本本轮均不自动裁剪。
3. 候选只限应用明确生成的对象键形状，且没有任何上述引用，并且对象最后修改时间已超过最少 7 天宽限。未知键、来源损坏、扫描不完整、限制超出、数据库/存储异常均保守保留或拒绝执行。
4. 工具限制专用 local 根目录或 OSS prefix，不遍历其他 Bucket / prefix，不删除任何数据库业务行。OSS 历史版本不枚举、不永久删除；添加 delete marker 不代表释放历史版本账单容量。

## 预演、执行与恢复

- 预演只读数据库和对象清单，生成有界、私密、带摘要的计划，记录候选身份、大小、时间与保留统计。终端仅输出统计、短错误码及计划摘要，不输出文件正文、凭据或存储地址。
- 执行必须显式指定已审阅计划的摘要和维护窗口确认。要求暂停全部应用写入者并核对任务状态，执行前重新读取完整引用与对象身份，旧计划、变化对象或新增引用不能删。工具还需独立并发锁和有界执行。
- 每个候选删除前，先复制到独立私密隔离归档，核对字节、SHA-256 与所选对象身份，落盘恢复元数据后才允许删除。数据库回滚不能撤销对象删除，所以不依赖单个数据库事务伪装原子性。
- 按对象保存执行/恢复状态；读取、复制、校验或持久化失败时不删除该对象。删除响应丢失时保留恢复材料并给出明确未知状态，不自动重复危险操作。
- 恢复使用已校验隔离归档，local 通过 Windows 不覆盖 rename / Linux renameat2(RENAME_NOREPLACE) 补回缺失原键；OSS 仅撤销经证明的本工具删除标记，不 PUT 或删除数据版本。不覆盖已经存在或身份不同的对象；同样要求维护窗口和显式命令。隔离归档本轮不自动过期清除。
- local 和 OSS 通过独立运维适配器实现，应用读写 Storage 接口保持不变。锁定 OSS SDK 1.4.0 的 DeleteObjectRequest 没有 If-Match；不能以 ETag HEAD 检查替代停止写入者。GC 写入禁用自动重试，并保存 delete marker / versionId 回执。默认只允许版本控制 Enabled 桶执行，Suspended / 未启用版本控制时拒绝 apply；仍可预演。依据：[官方 DeleteObject 文档](https://www.alibabacloud.com/help/en/oss/developer-reference/deleteobject)。
- 备份调度当前使用自身 state_root 的锁，不能假设独立 GC 自动互斥。本轮 GC 仅作为手工维护步骤，文档要求备份/导出/恢复/GC 不并行；实际执行必须证明全部应用写入者已停止，不增加在线自动清理任务。
- 已确认 PDF Worker 在 PUT 之后才登记临时对象；PUT 落盘但响应丢失时可能漏记。实现时将其对齐普通图片的先登记后 PUT，并以故障注入回归，统一 GC 仍负责强杀遗留对象。

## 验证与交付

先用隔离 PostgreSQL 与临时目录/模拟 OSS 验证：全部引用类别、跨账号、回收站与历史、失效任务输出、边界时间、未知键、损坏来源、扫描中断、并发变化、新增引用、复制/写盘/删除失败与回退、不可覆盖恢复及路径别名防护。再跑既有回归和独立审查。

操作文档必须含预演、维护前备份/停写、审阅、执行、结果核对、恢复和失败处理；同时明确本轮没有清理本地开发库、实际对象或云端数据。完成后更新 M1 状态和 task-evidence。

## 平台与故障保证

正式维护目标为 Ubuntu。POSIX 在删除前同步归档文件及其父目录；Windows 验证文件 flush、私密 ACL 与进程中断重试，不声称等同 POSIX 的可移植目录掉电保证。local 比较引用时对大小写/尾点空格别名保守保留；OSS 不改变键大小写。未做真实断电演练或真实 OSS 验收。
