# T14 定时备份、保留策略与失败通知

状态：2026-10-25 用户已确认推荐方案，允许维护窗口；只开发和隔离验证，不安装或启用公网定时任务。

## 目标与边界

- Ubuntu 宿主机上的独立执行器复用 `scripts/site_backup.py`，不放入 API 或 Worker，不授予应用容器 Docker socket。
- 实际命令执行限定 POSIX；Windows 在创建子进程前拒绝真实执行，仍可验证替身调度、跨平台状态和保留逻辑。进程组超时在无网络 Linux 容器单独验证。
- systemd timer 默认北京时间每天 03:00 触发；不补跑错过的时间。执行器再次检查可配置维护窗口，避免白天停服。
- 默认保留最近 7 份成功备份，可配置数量；这是本次确认的首期策略，不声明已实现架构文档建议的日/周分层或异地副本。
- 本轮不修改业务 schema、产品界面或依赖，不访问真实 OSS、模型与服务器，不变更现有业务备份，不 commit/push。

## 执行链路

1. 校验私密 JSON 配置、绝对路径、目录分离和子进程超时，取得整个运行周期的 OS 独占文件锁。
2. 发现配置的 Compose 项目与 db/api/worker；拒绝正在执行的迁移，记录原本运行的 API/Worker 容器 ID，并持久化恢复状态。
3. 只停止原本运行的写入服务，检查实际停止且 db 仍运行；外部写入者必须由操作者在启用时排除。
4. 在专用根的唯一目录中调用现有 backup CLI；备份原件、变体与 AI 冻结来源并校验。不在既有 bundle 中加入调度标记。
5. 不论备份成功与否，都在 finally 恢复原来运行且身份未变的服务；不拉镜像、不重建容器，不启动原先停止的服务。API 必须恢复 healthy。
6. 仅在新备份验证通过且服务恢复成功后登记成功回执，执行保留策略；失败绝不先删除旧备份腾空间。
7. 原子写入状态与脱敏失败事件。通知程序可选，参数为绝对可执行文件路径数组，shell=False，脱敏 JSON 通过 stdin 传递，有独立超时。默认不外发，失败事件可重试。

## 删除与故障保护

- 只管理回执登记的、严格命名的根目录直接子目录；未知目录、手工备份、暂存目录及损坏或旧 schema 备份均保留并报告。
- 回执位于独立状态根；校验 manifest 摘要、时间及完整 bundle 后按固定文件清单删除，拒绝路径别名、软链接、junction、硬链接与额外文件，避免广泛递归删除。
- `status` 展示脱敏状态；`retention-plan` 只读；`recover-services` 幂等恢复持久记录的服务；systemd ExecStopPost 在异常退出后调用恢复入口。
- 锁文件不删除；崩溃由 OS 释放锁。存在未完成恢复状态时，下次备份必须先恢复服务，不覆盖旧现场。
- 原始异常、stdout/stderr、连接串、笔记、对象键及配置值不进入日志、状态或通知；通知失败不掩盖备份或服务恢复失败。
- 本地告警和可选通知接口不等于外部主动推送已启用，不能覆盖宿主机断电或磁盘不可写；实际渠道与异地副本留待启用配置。

## 部署准备

服务器当前 db 无宿主机端口，交付单独的 `compose.backup.yaml`，仅在显式启用时映射 `127.0.0.1:55435:5432`。数据库连接文件使用同一 loopback 地址；原工具继续核对集群身份。启用覆盖配置可能重建 DB 容器，需另行维护窗口。宿主机需完整仓库、锁定的独立 Python 运维环境及 Docker CLI，不能直接复用现有 API 镜像。

## 验证

使用临时目录、合成备份、替身 Compose/备份进程和通知程序，覆盖完整顺序、失败恢复、并发锁、维护时间、容器身份变化、保留边界、路径攻击、超时、事件重试及敏感哨兵脱敏。运行根目录工具回归并检查 systemd 模板；保持开发库和公网停止/运行状态原样。现有全站备份的真实 PostgreSQL 验证不因调度替身测试被重复宣称通过。
