# 公网旧版数据库备份与恢复兼容设计

用户已要求补齐兼容公网旧版数据库的方案并完成本地隔离验证，暂不修改服务器或发布。承接IP HTTPS更新计划Task 4。旧版本依据上一轮只读记录为`c2e41a9f3b67`，本轮不连接公网；执行前仍须重新现场核对，不能把旧记录视为永久现状。

## 选择与范围

采用现有整站工具的显式schema profile（结构配置档），复用已验证的同步快照、pg_dump/pg_restore、OSS选定版本下载、哈希校验、私密暂存和空目标保护。默认仍使用当前head；新增备份参数只允许明确选择`c2e41a9f3b67`。不使用自动猜测、忽略缺表、create_all+stamp、绕过校验或先迁移源库。

备选为单独复制一份legacy备份工具，但重复安全逻辑、后续维护易漂移；仅提供pg_dump命令则缺少对象副本、引用一致性和恢复验证，不满足这次目标。

## 不变量

- 源库的revision、表集合及旧配置档的结构签名必须匹配；错误版本、缺表/多表、字段或约束漂移拒绝。禁止通过伪造revision接受当前表结构。
- 旧库22表（含迁移表），引用只来自`files`与`file_variants`；不存在的PDF/AI运行表不查询。回收站和历史业务数据仍完整备份，未就绪对象与明确可选缺失沿用现有口径。
- 同一个只读可重复读导出快照用于数据库指纹、引用清单与真实pg_dump；对象按版本ID或ETag条件下载，保留实际字节副本和哈希，模拟OSS必须走真实适配器。
- 维持bundle v1结构，`schema_revision`和严格表集合标识受支持版本；不伪装成当前head，不改变已有head bundle默认行为。未知profile拒绝校验/恢复。
- 只恢复新建且符合命名规则的空数据库及空目录；原始指纹和引用通过后，按实际profile撤销会话、清理临时凭证/旧加密AI凭据、停止待运行任务。旧schema不执行不存在的AI表归一化。
- 源库和源对象保持不变；恢复失败保留不完整标记，不覆盖重试；维护确认参数不自动停止任何服务。

## 隔离验收

在本机临时PostgreSQL集群创建随机独立源库，用真实Alembic迁移到c2，填入多账号、权限、笔记/版本/回收站、页面、任务与对象状态。真实备份/校验/空目标恢复，比较所有旧业务列和对象字节，确认归一化仅影响目标。

恢复副本再显式执行四段迁移至head，比较旧业务列投影、对象与账号密码/权限；新增PDF页码应为空，新增表初始为空。源库仍保持c2及原始指纹。另覆盖版本/结构漂移、必需对象缺失、可选对象错误、损坏bundle、非空目标、真实CLI与当前head回归。

本轮对象使用临时本地目录及Fake OSS客户端，不联系真实OSS、不读取真实环境或私钥、不调用模型、不购买资源、不提交推送部署。数据、输出和测试库均与`notes_dev`及公网分离；仅关闭/清理本轮拥有的测试资源。真实云端备份、OSS权限/版本与恢复耗时仍待后续授权验收。
