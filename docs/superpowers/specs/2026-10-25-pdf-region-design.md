# PDF 单页框选提问与来源定位

2026-10-25 用户已确认单页、单矩形方案；开发验证使用模拟模型，不调用真实付费接口。保留上一项 T14 未提交改动，不提交、推送或部署，不改日常开发库。

## 用户流程

在 AI 对话的 PDF 资料中，保留“指定页 / 整本 PDF”，新增“单页框选”。选择一个原 PDF 页码，加载私有阅读图，拖动画框或用百分比调整矩形；预览明确原页码、裁片尺寸和一次模型调用，未选区或未加载完成时不能发送。

后端只将裁片发送给模型，整页不随裁片一同发送。回答仍按原 PDF 页码引用。点击回答或保存笔记的来源，打开同一个稳定 page_id 对应的原页，在整页上高亮选区并自动居中/放大定位；提供“定位到选区”和“重置视图”，缩放平移时图片和选区保持一致。来源权限、删除失效与历史版本提示沿用既有机制。

## 数据契约

`PdfInput.mode` 增加 `region`，只允许一个 `page_numbers` 项且必须提供 `region: {x,y,width,height}`；比例相对后端 JPEG reading 页图，复用有界、有限、严格类型的 `ImageRegion`。`pages/all` 不接受非空 region。

内部来源继续为 PDF：`mode=region`，`pages[0]` 增加 region，仍冻结 page_id、原 PDF 页码、file_id、reading 对象身份与字节大小。公共 PDF 来源页增加可空 region；PDF 详情页项增加已授权 file_id，供复用 PrivateImage；region preview 返回 width、height、crop_width、crop_height，其他模式可为空。公共来源不暴露对象键。

兼容旧缺 kind 的 PDF 来源、整页/整本模式及历史页码。旧 PDF 请求缺省 region 在计算幂等 hash 时省略，不能让旧重试变成冲突。来源只允许 region 模式单页单框，失效来源在收费前拒绝；改标题/重排仍按稳定身份回看，不能把历史 revision 不同误判为无权访问。

## 处理与保存

复用普通图片的服务端有界 JPEG 解码与裁片逻辑：reading 图和裁片各不超过 8 MiB，像素不超过 2400²，最小 8×8；区域在 preview/创建运行前校验，在 worker 发送前重新校验来源并裁剪，裁片只在内存存在。整页/整本预览保持原轻量路径。

来源范围写入多轮历史说明、保存笔记的独立 provenance 和正文说明。ZIP 导出、离线验证和空环境恢复保留 PDF region；新版恢复器继续接受旧无 region 归档。新 region 归档需使用新版恢复器，不承诺旧脚本能读取新能力。现有 JSONB 足以承载，不增加数据库迁移或依赖。

## 验证与边界

后端仅在独立 `notes_test` PostgreSQL 与临时本地对象存储测试，使用双色 JPEG 解码模拟 provider 实际收到的 base64，证明只收到裁片。覆盖权限、版本/删除/替换、旧幂等 hash、旧 PDF、多轮、保存/导出/恢复。前端覆盖选择构建、切换/加载门禁、历史恢复和定位数学，保留独立标签会话屏障。

浏览器自动检查桌面与手机尺寸：反向框选、百分比、预览、引用定位、缩放平移、保存/编辑刷新、旧模式与普通图片回归。真实手机触控与公网部署另行验收，不扩大到多页、多框、PDF 文本选择或富文本选段。
