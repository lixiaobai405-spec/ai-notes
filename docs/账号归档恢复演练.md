# 账号归档的隔离恢复

工具 `scripts/restore_export.py` 将一个账号的 ZIP 恢复到独立、空白的本地 PostgreSQL 数据库和本地文件目录。它需要完整仓库与后端 Python 依赖；不提供网页合并导入，也不是 PostgreSQL 整站备份恢复工具。

## 目标与准备

- 只接受显式指定的本机 `postgresql+psycopg` URL，数据库名必须为 `notes_restore` 或 `notes_restore_` 加小写字母、数字、下划线。拒绝连接串 query 参数和覆盖目标的服务配置。
- 数据库必须已迁移到当前 Alembic head，所有应用表为空；工具锁定并检查应用表，不执行清空或覆盖。
- 文件目录必须不存在或为空，不能通过符号链接 / junction 指向其他目录，也不能与开发存储目录相同或重叠。
- ZIP 必须通过 v1 完整性、引用和业务字段校验。工具会先生成私有临时副本，再读取经过校验的字节，避免校验之后换包。
- 当前恢复工具单个文件对象最多 50 MiB；归档总量仍受 v1 的 512 MiB、元数据 32 MiB、50,000 条内容记录限制。来自自定义更大单文件上传配置的包可能通过离线校验，但会以 `restore_object_too_large` 拒绝恢复。
- 恢复账号使用新密码，默认普通成员。原管理员权限、密码、会话、邀请码、下载票据、模型和存储凭据不会恢复。

先检查导出包：

```powershell
backend/.venv/Scripts/python.exe scripts/verify_export.py '导出包.zip'
```

仓库提供独立本机演练数据库，端口 55434，不复用开发与回归测试库；容器卷保留演练数据，重复导入会因非空而拒绝：

```powershell
docker compose -f compose.restore.yaml up -d
$env:RESTORE_DATABASE_URL='postgresql+psycopg://notes:restore-local-only@127.0.0.1:55434/notes_restore'
$env:DATABASE_URL=$env:RESTORE_DATABASE_URL
$env:DEEPSEEK_API_KEY=''
$env:STORAGE_BACKEND='local'
$env:APP_ENV='development'
Push-Location backend
.venv/Scripts/python.exe -m alembic upgrade head
Pop-Location
```

以上固定凭据仅用于 `compose.restore.yaml` 的本机演练容器。若该库或存储目录已有数据，应另建专用空库和目录，不要清空旧库来绕过保护。

在新的 PowerShell 会话中设置 `RESTORE_DATABASE_URL`，避免把迁移时的 `DATABASE_URL` 继续用于日常开发启动。执行恢复时会隐藏输入并确认新密码：

```powershell
backend/.venv/Scripts/python.exe scripts/restore_export.py '导出包.zip' --storage-root '.local/restore-drill/restored-files'
```

自动演练可用 `--password-file '私密密码文件路径'`，文件仅包含新密码；不接受明文命令行密码。目标连接串只从 `RESTORE_DATABASE_URL` 读取，也可通过 `--database-url-env` 指定另一个变量名。工具不把账号内容、密码或连接串写到控制台。

## 恢复语义

保留 14 类内容集合中的 ID、修订号、时间、正文、历史 JSON 和关系。对象使用新的随机前缀及受控路径；文件名不作为路径。读取、写入及写后校验均检查 SHA-256 和长度。

AI 来源根据原页 / 文件 / 归档阅读图重新建立实际存储键，保留来源版本、原页码与图片选区。保存回答继续使用公开来源快照。对话新建请求标识、清空租约和内部输入，不恢复旧的模型调用环境。

PDF 还会补建应用读取状态所需的上传记录。原件存在的 PDF 使用已完成记录；已过期原件使用过期记录。失败图片和 PDF 补建失败任务，使页面仍能显示失败和人工重试入口；不会自动排队。已结束 AI 运行中的遗留 `running` 步骤转为 `failed`，保留已有部分回答；工具输出转换数量。

历史快照中已删除的笔记本和标签 ID 原样保留，不修改历史事实或创建虚构组织。当前页面可查看这些历史 JSON；现有产品没有历史版本一键回滚功能。

## 原子性与失败处理

先检查归档，再以单个数据库事务插入内容并写入本次独占对象前缀。已知未提交的失败会回滚行并清理该前缀；不删除其他目录或已有数据。磁盘与数据库之间没有分布式事务。

出现 `restore_commit_uncertain` 表示数据库提交结果无法确认：保留本次对象，不盲目删除。应先核对目标库的账号、集合计数及对象，再决定后续处理；再次执行会因非空库或非空目录被拒绝。`restore_cleanup_incomplete` 表示失败清理未全部完成，同样需要检查本次演练目录，不能当作成功。

退出码 0 表示恢复事务完成；其他情况仅输出短错误码，不回显数据库异常参数或笔记内容。成功也不会自动启动 API、Worker 或模型。

## 验收范围

恢复完成后，应让独立 API 指向恢复库和新文件目录，显式保持模型 Key 为空，用隔离浏览器验证正文、历史、回收站、PDF 原件、AI 回答和原页 / 选区。再导出一次，与原包的 14 集合及对象哈希比较；允许已报告的未完成步骤终态转换。

这验证账号内容可以重建。多账号整站 PostgreSQL 备份、真实 OSS 对象 / 版本备份、定时保留与失败通知、云端恢复仍须分别验收。
