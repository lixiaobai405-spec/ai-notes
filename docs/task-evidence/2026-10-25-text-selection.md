# 富文本选段提问与来源定位

日期：2026-10-25（Asia/Shanghai）。代码基线 `587ba36`，在前两轮未提交的 PDF region / T14 基础上继续。用户批准“选中文字提问、冻结原文与版本、来源定位、变更提示”后要求继续开发。本轮不提交、推送、部署或调用真实付费模型。

## 实现与边界

- 已保存富文本中选择一个连续片段，经“就选段提问”进入新对话；可跨段落、列表、换行和原子公式。草稿、保存中、失败或冲突时阻止选段提交；再次核对当前会话、版本与保存状态。
- 统一从历史 `body_json` 派生规范文本，不信任客户端可独立上传的 `plain_text`。输入为 `text: {note_id, revision, start, end, quote}`，偏移使用 Unicode 码点，严格整数、半开区间、最多 8000 码点；前端显式映射 ProseMirror UTF-16 位置，拒绝半代理对、空白和越界。
- 仅选段和当前对话历史进入文字模型，允许已有 Flash / Pro；不附带整篇笔记、页图进度或图像调用。总上下文沿用 32000 UTF-8 字节预算，不自动截断。Worker 调用前再次验证当前及历史引用，失效时不调用。
- 来源绑定原笔记、原版本、位置与原文。来源读取展示原版本规范全文、自动滚动并高亮，提示当前版本变化，可另行打开当前笔记。重复文本不靠搜索猜测定位，不覆盖当前草稿。
- 同一对话已成功引用且五字段完全一致的选段可以继续使用旧冻结来源，保留原标题与版本；任意其他旧版本选择仍拒绝。源笔记删除/权限不可用/历史缺失或损坏时，原文访问和新模型调用拒绝；已有回答可读可保存，恢复原笔记后可访问原版本。
- 保存回答的独立 provenance、ZIP、离线校验及空库恢复保留选段。导出/恢复核验历史身份、所有者与精确原文，回收站来源允许归档。新增来源需新版工具，旧无来源 / PDF / 图片归档保持兼容。
- 旧缺省 text 的请求 hash 保持兼容；原 PDF / 图片功能保留。复用 JSONB 与 NoteVersion，不增加迁移、依赖或 Key 配置。
