# 文件引用保留与安全清理

开发与验证日期：2026-10-25（Asia/Shanghai）；2026-10-26完成中断后状态核对与收尾。基线 `587ba36`，保留前序定时备份、PDF 框选、富文本选段未提交工作。用户明确批准“完整安全清理工具、默认预演、7 天、先归档后清理并支持恢复；本轮仅代码和隔离测试，不实际清理用户或云端数据”。设计与实施计划位于 `docs/superpowers/`。

## 实现

- `retention.py` 只读收集完整引用与确定性指纹，保留所有已登记 File/Variant，以及回收站、历史页面、PDF/上传/任务、AI 历史直接键和保存来源。坏结构、所有权不一致、缺链、未知来源或超限均阻止清理；不读取凭据、实际运行 token 或无关正文。
- PDF Worker 在 PUT 前登记尝试的键，覆盖 PUT 已落盘而响应丢失的回收缺口；只有这一顺序调整触及现有业务执行代码。
- `scripts/file_gc.py` 提供默认 plan、显式 apply、status、restore。计划绑定内容摘要、后端身份、完整引用指纹和对象身份，24 小时有效；允许键严格限应用生成格式，严格早于至少 7 天截止，未知键保留，单件128 MiB/总512 MiB/最多50000个对象。
- apply 要求两项停写确认、活动写入者为零、状态锁、数据库全局 advisory lock 与引用表 SHARE 锁，再核对全部引用和对象。锁不代替已发出的 PUT 停写；工具不自动停服务，不接入 timer，不删业务行。
- 全部候选先复制到独立私密 bundle、核对哈希并持久化，才逐件写删除意图并操作。删除失败或回执未知立即停止，不盲目重复。复制、校验、写盘和目录同步失败不会进入删除。
- local 原子不覆盖发布；OSSPrefix完整分页、Enabled 版本门禁、版本固定读取、无写重试。OSS 恢复仅删经完整分页证明的自有删除标记，保留数据版本与并发新 PUT；未知回执需要人工核验并保留归档。
- 原版本、回收站、已登记 expired/rejected 原件全部保留，不宣称净磁盘/账单空间已减少。隔离归档本轮不自动过期清除。无迁移、新依赖、API 或前端行为变化。

## 实际发现与修复

1. 初版归档只 fsync 文件，没有同步 `objects/` 目录项。独立完整 apply 调用 spy 证明删前未同步。补齐 POSIX 父目录同步与失败关闭，新增文件→目录→返回顺序、目录失败不删源的回归。
2. Windows 同一文件可由大小写/尾点空格别名访问。审查在临时目录复现引用键大写而实物小写时误列候选。plan/apply 均改为 local 保守等价保留，旧精确比较计划重验也拒绝；OSS仍精确大小写。
3. 初版 local restore 用 hardlink 发布，发布后强退可能留下两链接并阻止重试。改为 Windows 不覆盖 rename / Linux RENAME_NOREPLACE，真实子进程发布后立即 `os._exit`，目标单链接、stage消失、再次恢复及inventory正常。
4. 将总预算接入真实 inventory/分页/分块读取循环，成功写入回执不被后置 deadline 覆盖；超时停止后续动作。
5. 已 expired 的 PDF 上传仍保留原件，但其 uploading 导入不永久阻塞维护；重新激活后的 pending/received 上传再次阻止apply。现有活动任务/残余租约继续保守拒绝。

## 平台与证据限制

Linux验证只复制7个明确GC源码/测试文件及2个空package初始化文件到仓库外 `file-gc-linux/`，未复制环境文件、备份、凭据或用户存储。容器使用 `--network none --read-only --cap-drop ALL --security-opt no-new-privileges` 和单独 `/tmp`，不挂载开发卷。92项实际运行包含FakeOSS版本分页和标记恢复，不能作为真实OSS验证。

Windows检查私密DACL与进程崩溃后的逻辑恢复，但标准库没有可移植POSIX等价目录掉电刷盘保证；正式执行目标Ubuntu。Linux容器真实fsync/renameat2和调用顺序也不等于主机断电演练。无版本/Suspended桶只允许预演，数据历史版本永久清理不在本工具范围。

操作说明包含配置、独立运维环境、只读预演、维护前备份/停写、审阅摘要、执行/核验、恢复和未知结果处理；见 [文件引用保留与安全清理](../文件引用保留与安全清理.md)。新公共API为零，因此本轮没有重新生成或改动已有OpenAPI/TypeScript契约。
