## 真实镜像缓存验证

环境：Windows / Docker Desktop Linux Engine，Docker 29.8.0、BuildKit v0.33.0，`linux/amd64`。使用本次创建的专用 builder，原应用源码复制到过滤后的隔离上下文，未发送真实环境文件、私钥、私人目录或 `AGENTS.md`。源码变化只发生在隔离副本，不修改实际业务源码。

| 场景 | 用时 | 实际观察 |
|---|---:|---|
| 前端首次构建及本地缓存导出 | 96.59 秒 | 依赖安装、生产构建及镜像加载通过 |
| 前端仅改源码后热构建 | 14.72 秒 | `npm ci` 显示 `CACHED`，`npm run build` 重新执行 |
| 新建另一独立 builder，仅导入导出的本地缓存 | 41.53 秒 | 日志出现 `importing cache manifest`，`npm ci` 仍为 `CACHED` |
| 后端首次构建及本地缓存导出 | 1119.98 秒 | 包含专用 builder 首次启动、基础镜像及完整依赖下载；成功 |
| 后端仅改源码后热构建 | 13.80 秒 | `RUN pip install --no-cache-dir -r requirements.lock` 显示 `CACHED`，只重跑后续层 |

上述为本机一次观测，包含不同基础镜像下载、builder 初始化、缓存传输和镜像加载开销。它证明依赖层可复用、可在独立 builder 中恢复，不构成 GitHub GHA 缓存实际运行或固定提速倍数的证明。

复用镜像集成覆盖 IP 证书、HTTP→HTTPS、SPA 资源、API / 身份转发边界、错误 IP 拒绝、安全响应头、64 秒 SSE（首字节 0.048 秒，32 次心跳）、20 / 50 MiB 合成上传，以及重启后证书 / 数据保留。仅在内部 Docker 网络和合成上游执行，不代表真实业务或生产性能验收。

## 真实 Linux 离线包验证

构建使用 `python:3.12-slim-bookworm`、Linux / x86_64、CPython 3.12、glibc 2.36。在线构建只读取专用白名单中的脚本及锁文件；导出数据保存在仓库外本地验证目录。断网安装使用官方干净基础镜像、`--network none --read-only --cap-drop ALL`、临时可写 `/tmp`，只读挂载离线包；不挂载应用、数据库、OSS 或环境配置。

| 用途 | wheel 数 | 包内清单文件数 | 内容大小（不含 manifest） | 禁网安装 |
|---|---:|---:|---:|---|
| monitoring | 5（含 pip） | 11 | 12,356,357 字节 | 8.23 秒，pip 引导、4 个依赖、`pip check` 与全部导入检查通过 |
| backup | 46（含 pip） | 52 | 37,463,220 字节 | 13.48 秒，pip 引导、45 个依赖、`pip check` 与全部导入检查通过 |

最初 monitoring 在线 Docker 构建成功，原始导出保留。backup 在成功下载全部 46 个 wheel 后，被过紧的 METADATA 上限拒绝，未完成 Docker 导出。失败日志中的精确文件名已保留；针对每个文件，通过官方 PyPI 对应版本 JSON 获取 URL / SHA-256，重新取得或复用内容并验证官方哈希，没有替换版本或改包。恢复下载只用于仓库外本地验收，不改变生产工具下载方式。

最终源码在干净 Linux 容器中执行真实 `build()` 流程，以一次性验证适配器将其 pip 下载输入改为上述预置 wheel 的 `--no-index --find-links /wheels`；平台检查、固定依赖选择、真实 pip download、完整性 / 元数据验证、manifest 与安装器输出均由最终工具生成。两种最终包再次在 Windows 校验，确认安装器及两份源锁文件 SHA 与工作区一致，然后执行表中禁网安装。**该结果是“官方哈希核验 + 最终工具 Linux 本地预置 wheel 构包 + 最终包禁网安装”，不等同于最终源码的常规在线 Dockerfile 完整重建或 GitHub 工作流执行。** 在线下载阶段仍需要构建机网络；提交后的工作流会直接使用最终源码。

最终安装器 SHA-256：`cb6c69b6919dc36581e2d3dca75ca088b5aedaba447dd0cbad09a727e3346f76`。最终 manifest SHA-256：monitoring 为 `74ecc55ac983865c55b87796dfa888f2258a4a0bd1fd6c1a1f21802c5acbfec2`，backup 为 `caa605ea2a28598a6560810ce44546a39beb973501ae38eb4f31d2a761dc1202`。

两种最终包的安装容器均将系统 `pip`、`ensurepip` 目录用空只读挂载遮蔽，先断言它们没有可用的版本 / 引导入口，再运行安装：通过。对真实 wheel 的隔离副本翻转一个字节后，校验返回 `bundle_integrity_mismatch`，损坏包未用于安装。

## 审查修复与工作区保护

独立规格审查复现：包含 `..` 的 bundle 路径可以绕过旧的词法重叠检查，在包内创建新虚拟环境。现改为先拒绝原始路径和祖先中的软链接，再规范化路径，最后执行重叠判断。独立复验返回 `venv_overlaps_bundle`，新目录不存在、子进程调用为 0；另保留合法相对路径 / `..` 校验用法。相关回归先失败、修复后通过。

真实构建另发现 `pydantic==2.14.1` wheel 的合法 METADATA 为 133,006 字节，超过旧的共用 128 KiB 文本上限。使用官方哈希验证的原 wheel 复现 RED/GREEN 后，仅为 METADATA 设置独立 1 MiB 上限；锁文件、WHEEL、manifest 及身份 / tag / 哈希检查保持原限制。新增回归覆盖实际大小、恰好上限和超限拒绝，两个独立审查均复核通过。

CI 的 pip 下载缓存键纳入运行 / 开发两份锁文件；所有新 GHA 缓存显式使用 `version=2`。没有新增业务依赖或数据库结构变更。

开始前记录 14 个已有 modified / untracked 文件的 SHA-256；本次只在已有 README 中加入入口，其余 13 项按基线核验保留。最终差异、忽略规则与敏感路径检查通过；AGENTS.md、`.local` 和仓库外制品未纳入 Git。仅移除本轮创建的两个专用 builder，未执行 prune 或修改用户其他 Docker 资源。完整构建 / 安装日志及原始、最终制品位于本地验证目录，路径见本地运维记录，不纳入 Git。
