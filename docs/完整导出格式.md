# 当前账号完整导出

在“我的笔记”展开“完整导出”，点击“生成并下载 ZIP”。归档包含当前账号已保存到服务端的数据，包括回收站；浏览器中尚未同步的编辑和草稿不在其中。导出不会调用模型。

这是账号内容归档。命令行空环境恢复工具及其本机演练见 [账号归档恢复演练](账号归档恢复演练.md)；网页合并导入、整站数据库加对象存储备份恢复、定时备份仍待完成，不能仅凭账号恢复通过认定整站备份恢复已验收。账号密码、登录会话、邀请码、下载票据、模型 Key、OSS 凭据和环境配置均不属于归档内容。

## 下载与限制

- 接口：`POST /api/v1/exports/archive`，要求当前账号认证、同源请求及 CSRF。接口不接受目标账号参数，管理员也只可导出自己的内容。
- 上传、图片 / PDF 处理、AI 回复仍在进行时，返回 `409 export_busy`；过期上传需等待维护回收。已经结束的失败处理保留状态，不在导出时重试。
- 使用 PostgreSQL 只读 REPEATABLE READ 快照提取元数据，再读取应用已登记的私有对象，不扫描 Bucket。期间的新编辑不进入本次快照。
- 先在临时磁盘中完成 ZIP 和校验，再返回下载。必需原件 / 变体缺失、大小或原件现有 SHA-256 不符时整包失败，不交付部分成功包。返回 `409 export_incomplete` 或 `503 storage_unavailable`。
- 默认未压缩内容总量上限 512 MiB、内容记录总量 50,000 条、`data.json` 与 `manifest.json` 元数据预算 32 MiB；超限返回 `413 export_too_large`。这些设置可降低，内容总量不能超过当前浏览器实现的 512 MiB 上限。
- 默认构建时间预算 120 秒；在数据库读取、每个对象读取前后及打包结束检查。同步存储读取在返回后检查超时，因此不保证精确在第 120 秒中断。超时返回 `503 export_timeout`。前端另设请求超时、取消及会话切换保护。
- 每个 API 进程最多一个生成 / 下载请求；其他请求返回 429。临时文件在失败或传输结束 / 中断后关闭。浏览器接收 ZIP 后暂存在内存，交给浏览器下载；不写入应用草稿或持久缓存。

可通过 `EXPORT_MAX_BYTES`、`EXPORT_MAX_ROWS`、`EXPORT_MAX_METADATA_BYTES` 和 `EXPORT_MAX_SECONDS` 配置上述服务端限制。更大规模、后台生成和断点续传尚未实现。

## ZIP v1

文件名为 `ai-notes-export-YYYYMMDDTHHMMSSZ.zip`。用户原始文件名只作为元数据保存，不用于生成归档路径。

| 路径 | 内容 |
|---|---|
| `manifest.json` | 格式标识 `ai-notes-export`、`version: 1`、导出时间、账号基本标识、集合计数、逐项 payload 清单 |
| `data.json` | `collections` 对象中的 14 类内容集合 |
| `objects/{file_id}/original` | 登记的原图、原 PDF 或 PDF 页原图 |
| `objects/{file_id}/variants/{variant_id}` | 登记的阅读图或缩略图，通过 kind 识别 |

`manifest.payloads` 中每项包含 `path`、`bytes` 和 `sha256`，覆盖 `data.json` 及全部对象；清单自身不递归计算哈希。SHA-256 用于检查损坏，不是防篡改签名。

14 类集合为：`folders`、`notebooks`、`tags`、`notes`、`note_tags`、`note_versions`、`files`、`note_pages`、`file_variants`、`pdf_imports`、`ai_conversations`、`ai_runs`、`ai_steps`、`ai_saved_notes`。保留稳定 ID、修订号、时间和现有关系。笔记正文与历史快照保留 JSON；AI 回答保留 Markdown 字符串。

`files.original_path` 和 `file_variants.path` 指向归档对象，实际存储键不会导出。已经回收的过期上传保留文件元数据，`original_path: null`、`original_unavailable_reason: upload_expired`。图片校验不通过后，原有 Worker 会主动删除拒收的原件；这类非 PDF 的 rejected 文件同样保留元数据和错误码，并记录 `original_unavailable_reason: image_rejected`，不把业务已删除的原件作为必需附件。被拒绝的 PDF 原件仍然保留，照常导出。AI 来源保留笔记 / 页面 / 文件 ID、页码、来源版本与选区，新增 `reading_path` 指向归档阅读图；不会以来源 JSON 中的存储键读取对象。

原件有数据库 SHA-256 时会与现存字节比对。变体表目前只有长度，因此导出可检查长度并为当前字节生成 SHA-256，不能发现导出前已经发生的同长度变体替换；清单哈希可检查导出后的损坏。

`resume_processing: false` 表示归档不携带任务队列、租约、请求去重哈希和模型内部输入。命令行恢复工具会建立新的运行标识与必要运行记录，并保持已结束状态，不能直接把这些 JSON 当数据库备份导入或自动恢复付费调用。

## 离线校验

使用 Python 标准库即可运行，不需要应用环境、数据库、网络或凭据：

```powershell
python scripts/verify_export.py '导出包路径.zip'
```

校验器不解压、不恢复，只检查允许的路径和条目类型、重复 / 缺失 / 额外条目、版本、大小、SHA-256、集合计数、当前所有者与基础引用、附件映射及 AI 来源页面关系。退出码 0 表示校验通过；失败时仅输出简短错误码。

历史快照可能引用之后删除的文件夹、笔记本或标签。这些历史 ID 按原样保留，不当作当前外键拒绝；当前空环境恢复工具同样原样保留历史 JSON，不创建虚构组织。校验器本身不证明数据库恢复成功，也不验证笔记正文的事实正确性。

## 文字选段来源扩展（2026-10-25）

`ai_runs.source` / `ai_saved_notes.source` 支持 `kind: "text"`，字段为 `kind`、`note_id`、`title`、`revision`、`start`、`end`、`quote`。文字来源没有 `pages`、对象键或附件路径，保存的 `cited_page_numbers` 为空。偏移按从历史 `body_json` 派生的规范文本 Unicode 码点计数，区间左闭右开；精确规则见 [功能说明](AI回答保存为笔记.md#富文本选段提问与来源定位2026-10-25)。

导出、离线校验与恢复均核验原笔记种类、所有者、历史版本身份与选区原文一致。源笔记已在回收站仍可归档；恢复后保持删除状态，恢复源笔记后才允许读取来源。沿用格式版本 1 的可选来源扩展，旧无来源 / PDF / 图片归档仍可读取，带文字来源的新归档需新版校验与恢复脚本。
