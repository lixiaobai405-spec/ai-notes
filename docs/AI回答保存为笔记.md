# AI 回答保存为笔记

2026-10-20：在已有文字与 PDF 对话上增加“保存为笔记”，随后接入 Markdown、数学公式排版与普通图片整图 / 单矩形选区来源。保存基础阶段的迁移与验收见 [阶段证据](task-evidence/2026-10-20-save-ai-answer.md)。普通图片阶段后端全量 265 项、前端 11 项、配置 6 项及构建通过，本机桌面 / 手机尺寸浏览器与真实整图、裁片调用通过。当前仍是本机功能，不代表完整 M1 或云端部署已完成。

## 使用方式

1. 在“AI 对话”中等待一轮回答完整生成。只有成功完成且正文非空的回答可以保存；排队、生成中、取消、中断、失败或截断的回答不能保存。
2. 点击该回答下的“保存为笔记”，确认标题，选择目标笔记本；也可保存为未分类笔记。
3. 确认后生成一篇普通文字笔记，可点击“打开笔记”继续编辑。正文保留本轮问题、回答和生成模型；附有 PDF 或普通图片时，还保留名称、当时的来源版本、所选页码与回答引用的合法页码。普通图片另保留整图 / 选区模式及选区位置。
4. 在笔记的独立来源区域打开引用原页，也可展开本次来源的全部原页；图片选区会在原图中标出。来源阅读器支持返回笔记。

保存直接使用服务端已经持久化的回答，不重新生成、不再调用模型，也不要求用户配置个人 Key。浏览器只提交标题和笔记本 ID，不能借此替换服务端的问题、回答或来源。

## 编辑、重复保存与回收站

首次保存会在同一数据库事务中创建文字笔记、初始历史版本与回答来源关联。每个用户的同一轮回答最多关联一篇保存笔记；并发点击、网络响应丢失后的重试和再次保存均返回已有笔记，不生成副本。

之后可以在笔记中修改标题、正文与所属笔记本。再次保存这轮回答会返回现有笔记的当前信息，不覆盖这些编辑。若笔记已移入回收站，再次保存仍指向该笔记，不自动恢复或重建；需要从回收站恢复后继续使用。

来源信息独立于可编辑正文保留。删除或改写正文中的“PDF 来源”或“图片来源”文字，不会改变独立来源区域记录的原始名称、版本、原页引用和选区位置。普通正文中的有效 `[[p:N]]` 标记在保存后变为可读页码，实际原页入口由来源区域提供；代码、公式、链接标签和未选页标记均保持字面内容。

## 来源权限与失效

回答、保存笔记与来源读取均按私人所有者检查，管理员也不能绕过其他成员的权限。公开来源快照只包含来源类型、笔记 ID、标题、版本、选择模式、page_id、当时页码及可选的归一化选区，不包含私有对象键或文件存储元数据。

原 PDF 或图片笔记删除后，已经完成的回答仍可保存，保存笔记中的文字与来源快照继续保留。打开原页仍须通过现有来源校验：来源已删除或页图身份失效时显示不可用，不因保存回答而复制、恢复或公开原件。来源笔记版本发生变化时，阅读器会提示引用来自历史版本。

## 普通图片与矩形选区

1. 在图片笔记中上传照片或截图，等待 Worker 生成阅读图。PDF 转换出的原页不列入普通图片选择；后来另行上传的普通图片可以选择。
2. 在“AI 对话”选择普通图片资料、笔记和一张图片，使用“整张图片”或“框选局部”。可在预览上拖动画框，也可用百分比字段通过键盘调整矩形。
3. 预览显示本次图像尺寸与计划调用次数；发送后使用 DeepSeek Flash，一轮一个图像、一次模型调用。所有登录成员共用现有 Key，真实值继续仅放在本机后端私密配置中，不提供个人 Key 入口，也不返回浏览器。
4. 回答中的合法页码引用可打开原图；框选来源会显示原来的矩形范围。保存回答后保留同一来源入口，编辑正文不会改变原始选区。

浏览器只提交笔记 ID、版本、page_id 和归一化矩形，不提交文件 ID、对象键或图片 URL。服务端校验所有者与最新笔记版本，从私有存储读取已处理的 JPEG 阅读图，实际解码后按阅读图尺寸裁剪；局部模式只把裁片发送给模型，整图不会随裁片一起发送。裁片只在内存生成，不创建公开对象或另存文件。

每轮只选一张图片和最多一个矩形；每篇笔记最多 200 张普通图片，超过时明确提示拆分。阅读图与输出裁片各不超过 8 MiB，阅读图最多 576 万像素，整图 / 裁片的宽高均至少 8 像素。损坏图片、过小选区、过期版本或失效来源会在调用模型前拒绝。当前不支持多张图片同时提问或多个框；PDF 单页框选与富文本选段见下文。

来源冻结稳定的 page_id、图片身份、当时页序、笔记版本和选区。图片重排后仍打开同一张图，页序标签保留提问时的值；不会按当前排序误开其他图片。来源删除或原图身份变化后，原图入口不可用；后续调用继续检查来源，未知结果不会自动重发收费请求。更换来源笔记或来源类型请新建对话。

本机验收使用两张生成的 1200×800 图片，现有共享模型整图调用 1 次（返回用量 800 tokens）和右半 600×800 裁片调用 1 次（620 tokens）；前者识别左右两侧，后者只读取右侧。桌面 1440×1100 与手机尺寸 390×844 通过反向拖框、百分比精确调整、尺寸预览、引用原图、100% / 125% 缩放及平移后的选区定位、保存 / 编辑 / 刷新和重排后同图回看；后续复验无新增模型调用。浏览器无应用异常、HTTP 失败或 Key 泄漏，既有登录 pattern / favicon 提示单独识别。手机尺寸检查不代替真实手机触控验收。

## Markdown 与数学公式

聊天生成过程中显示原文，结束后由服务端统一解析为受控 Tiptap JSON，聊天和新保存笔记共用解析规则。支持一至六级标题、粗体、斜体、删除线、有序/无序列表、引用、行内代码、代码块、分隔线和显式 HTTP(S) 链接。有序列表保留起始序号，代码中的公式与引用标记不被解释。

公式支持 `$...$`、`$$...$$`、`\(...\)` 和 `\[...\]`。行内/独立公式保存为编辑器的 `inlineMath`/`blockMath` 节点，保留 LaTeX；显示使用现有 KaTeX，宽公式和代码局部滚动。无效公式显示原 LaTeX 和提示，不影响其余回答。JSON 导出保留结构，Markdown 导出保留公式与代码内容，特殊格式转换仍可能有损。

HTML 标签按文字显示；外部图片只保留说明，不自动请求图片地址。链接仅允许 HTTP(S)；KaTeX 禁用受信任扩展并限制展开次数与尺寸。单公式超过 8 KiB 时按原文保留；全文的解析输入/输出预算为 250000 字节，另有 8000 个解析标记/分隔符与 16 层嵌套限制（此处不是服务商计费 token），超限时整条回答回退原文，不截断原回答。回退时不猜测代码中的引用，仍可从来源区域打开全部原页。

旧聊天读取时也应用排版；已保存笔记保留当前正文和编辑记录，不自动重写。保存正文仍受现有笔记的大小与结构限制，超过限制时提示无法保存。表格和远程图片嵌入尚未加入。

实现参考：[MarkdownIt 安全配置](https://markdown-it-py.readthedocs.io/en/latest/security.html)、[数学解析插件](https://mdit-py-plugins.readthedocs.io/en/latest/#math)、[KaTeX 安全配置](https://katex.org/docs/security.html)。

## 接口与迁移

| 接口 | 用途 |
|---|---|
| GET `/api/v1/ai/conversations/{conversation_id}/saved-notes` | 查询本人对话内各轮回答的保存状态与对应笔记当前信息，包含回收站状态 |
| POST `/api/v1/ai/runs/{run_id}/save-note` | 提交 `title`、可选 `notebook_id`，保存成功回答或返回已有保存结果 |
| GET `/api/v1/notes/{note_id}/ai-answer` | 查询本人未删除笔记的独立回答来源；普通笔记返回 `null` |
| GET `/api/v1/ai/image-notebooks` | 最近更新的最多 100 篇本人有已处理普通图片的笔记 |
| GET `/api/v1/ai/image-notebooks/{note_id}` | 本人普通图片的稳定 page_id、当时页序及授权阅读所需文件信息 |
| POST `/api/v1/ai/image-preview` | 校验单图 / 矩形，返回原图与裁片尺寸、计划一次调用；不调用模型或创建运行 |

原页继续通过 GET `/api/v1/ai/runs/{run_id}/source-pages/{page_id}` 读取授权后的页面信息。写请求沿用 CSRF、Origin 与账户状态校验。

创建运行的接口新增可选 `image: {note_id, revision, page_id, region}`；整图的 region 为空，选区包含 x、y、width、height，均为图片宽高的比例。image 与 pdf 不能同时提交。图片阶段沿用现有来源 JSON，无需新增数据库迁移，旧 PDF 来源快照继续兼容。

排版阶段无需新增数据库迁移。`RunOut` 新增只读 `formatted_answer`：生成中为空，终态返回 `body_json` 与 `fallback`；原始 `answer` 不变，SSE 的 `done` 携带格式树，delta/state 不重复发送格式内容。浏览器对每个 SSE 事件及未完成残留单独执行长度限制，合法事件合并在同一网络块时不会误报。

迁移 `2ef16e7ca892` 接在 `63b9d8343e02` 之后，为 `ai_runs` 增加所有者与运行 ID 的联合唯一约束，并创建 `ai_saved_notes`。关联表以组合外键约束运行和笔记归属，以唯一约束保证一轮回答只保存一次、一篇笔记只关联一轮回答，同时保留安全来源快照与引用页码。部署前应备份应用数据库，再执行 `alembic upgrade head`；当前实际执行结果见阶段证据。

## PDF 单页框选来源（2026-10-25）

PDF 在“指定页 / 整本”之外增加“单页框选”：选择原页，拖动或百分比调整一个矩形，核对裁片尺寸后提问。后端只发送裁片，回答继续引用原 PDF 页码。详见 [PDF 框选说明](PDF选页与整本AI对话.md#单页框选与来源定位)。

保存正文会说明原 PDF 页码和选区比例，独立来源快照保留稳定页面与矩形。点击聊天或保存笔记的来源，会在整张原页上显示绿色框并自动居中定位；“定位到选区”可在缩放平移后重新找到范围，“重置视图”回到整页。来源已删除/替换时继续拒绝读取，不因保存而复制或公开原件。

ZIP 导出、离线验证与新版恢复工具保留 PDF region；旧无选区归档继续兼容，新选区归档需新版恢复脚本。本阶段沿用已有 JSONB，不增加迁移、存储对象或模型 Key 入口。

## 富文本选段提问与来源定位（2026-10-25）

在“我的笔记”打开已保存的文字笔记，用鼠标、键盘或手机文字选择选中一个连续片段，点击“就选段提问”。系统新建一段对话，显示所选原文、标题和版本；输入问题后发送。草稿、保存中、保存失败或冲突时需先完成保存，不会把未保存内容绑定到旧版本。

选区可以跨段落、列表、换行和公式，最多 8000 个 Unicode code point（码点）；中文和 emoji 各按实际码点计数，组合字符不做归一化。后端从历史 `body_json` 派生原文并精确核对选区，只把所选文字与本段对话历史交给模型，不自动发送整篇正文。选段支持已有文字模型，仍受 32000 UTF-8 字节上下文预算约束。

点击聊天或保存回答笔记里的“查看原文选段”，会打开原笔记当时版本的只读全文并自动滚动、高亮对应范围。“定位到原文选段”可再次定位，“打开当前原笔记”另行打开当前编辑页。原文后来修改时显示版本变化提示，不猜测在新正文中的位置，也不覆盖草稿。已经成功引用的完全相同选段可在同一对话继续按旧版本提问；使用修改后的正文需重新选择。

源笔记删除、历史版本缺失或权限不可用时，来源访问和后续模型调用停止；已有回答及其来源摘要仍保留，恢复笔记后可以重新访问原版本。保存回答保留独立文字来源，编辑回答正文不会改变选段。ZIP 导出、离线验证与新版恢复器保留原笔记、版本、码点范围及原文；旧格式继续兼容，新文字来源归档需新版工具。

接口使用可选 `text: {note_id, revision, start, end, quote}`，与 `pdf` / `image` 互斥；`start/end` 为规范原文中左闭右开的码点偏移。GET `/api/v1/ai/runs/{run_id}/source-text` 返回授权原版本全文、来源和变化标记，不调用模型。复用现有 JSONB 与历史表，无新增迁移、依赖或 Key 配置。实现与验证范围见 [本阶段记录](task-evidence/2026-10-25-text-selection.md)。
